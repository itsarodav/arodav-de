### 1.3 — El sistema y el problema

**contexto_de_negocio_en:** `ODILO delivers digital archive and preservation services to both public institutions and private organizations. Before I joined, this product vertical had never had anyone in a design role — every visual decision was made ad hoc by engineering.`

**metrica_objetivo:** `Adopción de componentes del design system por desarrolladores que no los construyeron`

**sintoma_visible_es:** `Tres generaciones de iconografía conviviendo, colores escritos a mano en cada hoja de estilos, sin un lenguaje visual compartido — cada pantalla definía sus propios botones, avisos e iconos.`

**causa_raiz_en:** `No design system, no token layer, no governance. Each screen solved design decisions independently, repeating work across every module.`

**causa_raiz_es:** `Sin design system, sin capa de tokens, sin gobernanza. Cada pantalla resolvía las decisiones de diseño de forma independiente, repitiendo trabajo en cada módulo.`

**job_to_be_done_en:** `Functional: establish a token layer and reusable components so every design decision is resolved once, in the right abstraction. **job_to_be_done_es:** `Funcional: montar una capa de tokens y componentes reutilizables para que cada decisión de diseño se resuelva una sola vez, en la abstracción correcta. Negocio: dar consistencia visual al producto de cara a los clientes, sin duplicar esfuerzo en cada módulo.`

### 1.4 — Decisión y construcción

**decision_tomada_en:** `Tokens first, screens later. I reversed the usual order — defining the token architecture before touching a single component, running documentation in parallel, and leaving migration for last. Every component was built from scratch with its variants, states, and accessibility baked in from the first commit, not bolted on afterward. Figma variables were wired to their CSS counterparts so both tools stay in sync without manual translation.`

**decision_tomada_es:** `Tokens primero, pantallas después. Invertí el orden habitual — definir la arquitectura de tokens antes de tocar un solo componente, documentación en paralelo, y migración al final. Cada componente se construyó desde cero con variantes, estados y accesibilidad integrados desde el primer commit, no parcheados después. Las variables de Figma se conectaron a sus equivalentes en CSS para que ambas herramientas se mantengan sincronizadas sin traducción manual.`

**alternativa_descartada_en:** `Building components first and retrofitting a token layer underneath — rejected because any change to the color or typography system would have forced rewrites across every component. Starting from tokens compels you to settle the hard questions upfront: what belongs at the primitive level, what's semantic, and what hinges on usage context.`

**alternativa_descartada_es:** `Crear componentes primero y meterles una capa de tokens por debajo después — descartado porque cualquier cambio en el sistema de color o tipografía habría obligado a reescribir todos los componentes. Empezar por los tokens te obliga a resolver antes las preguntas difíciles: qué es primitivo, qué es semántico y qué depende del contexto de uso.`

**proceso_con_ia_en:** `Now extending the playground with agentic skills and automated workflows — the goal is to make consuming a token or component feel effortless for any developer on the team, even without prior context.`

**proceso_con_ia_es:** `Ahora mismo estoy ampliando el playground con skills agénticos y workflows automatizados — el objetivo es que consumir un token o un componente sea algo natural para cualquier dev del equipo, incluso sin contexto previo.`

### 1.5 — Impacto

**metrica_antes:** `0 tokens, 0 shared components, 3 coexisting icon generations, colors hardcoded per stylesheet`
**metrica_despues:** `440 design tokens, 190+ unified icons (60% originally authored), 110 live component instances from 4+ production components, 24% of instances built by the rest of the team without direct intervention`
**plazo:** `Sistema en producción desde abril 2026, en evolución continua`

### 1.6 — Narrativa

**resumen_ejecutivo_en:** `MDDS is the design system I built solo for ODILO's Archive & Preservation product. Before it existed, every screen rolled its own buttons, notices, and icons — three coexisting icon generations, colors hardcoded in every stylesheet, no shared visual language. **metrica_objetivo:** `Reducir el onboarding de un icono nuevo a un solo paso: soltar el SVG en una carpeta`

**causa_raiz_es:** `El cuello de botella nunca fue el dibujo — es todo lo que pasa después. La distribución es el único problema que importa de verdad cuando el equipo que consume los iconos no es el mismo que los produce.`

**job_to_be_done_en:** `Functional: let anyone find, inspect, copy, and use any icon — no Figma, no install, no asking around. ### 4.4 — Decisión y construcción

**decision_tomada_en:** `Zero production dependencies — because an icon catalog is infrastructure, and infrastructure must outlive the framework choices of the teams that rely on it. SVGs are normalized at load time (stripping width/height, injecting ARIA attributes) while source files remain untouched as pure design artifacts. Modals use native <dialog>, syntax highlighting runs on a purpose-built regex tokenizer, and copy relies on the Clipboard API with an execCommand fallback for legacy browsers.`

**decision_tomada_es:** `Cero dependencias de producción — porque un catálogo de iconos es infraestructura, y la infraestructura tiene que sobrevivir a las decisiones de framework de los equipos que dependen de ella. Los SVGs se normalizan en tiempo de carga (quitando width/height, inyectando atributos ARIA) mientras los ficheros fuente se quedan intactos como artefactos de diseño puros. Los modales usan <dialog> nativo, el resaltado de sintaxis corre sobre un tokenizador regex hecho para esto, y el copiado usa la Clipboard API con fallback a execCommand para navegadores antiguos.`

**alternativa_descartada_en:** `React or any framework — rejected outright. If the catalog requires React to open, it dies the day the team migrates to something else. Also rejected: pulling in a syntax highlighting library for a catalog that only needs to display one language. A regex tokenizer covers it in a fraction of the weight.`

**alternativa_descartada_es:** `React o cualquier framework — descartado de raíz. Si el catálogo necesita React para abrirse, muere el día que el equipo migre a otra cosa. Solo el runtime de React pesa ~40 KB — 3.7 veces la aplicación entera de Prelude, antes de escribir una sola línea de producto. También descartado: traerse una librería de syntax highlighting para un catálogo que solo necesita mostrar un lenguaje. Un tokenizador regex lo cubre con una fracción del peso.`

**proceso_con_ia:** `No se usó IA en el proceso de este proyecto.`
